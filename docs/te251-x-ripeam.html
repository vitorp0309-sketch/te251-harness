Projeto TE-251 · comparação com o chatbot do artigo RIPEAM

TE-251 × RAG RIPEAM

Os dois são “LLM + contexto buscado fora do modelo”. A diferença está no que se busca e em quem decide buscar. O RIPEAM sempre puxa 3 trechos de um PDF que não muda. O TE-251 deixa o modelo escolher ferramentas que leem um carro que muda a cada segundo, e depois confere a resposta.

O que é igual

Python, prompt de grounding (“responda só com o contexto”), um laço de chat e uma interface web. O padrão de RAG do RIPEAM vira uma das ferramentas do TE-251.

O que muda

Dado vivo com idade, ferramentas escolhidas pelo modelo, checagem de números, tudo local em duas máquinas com GPU e réplica por MQTT.

O que não serve

gpt-4o-mini e embeddings da OpenAI (nuvem é proibida), o índice Chroma do RIPEAM, o venv de Windows e a chave exposta no código, que precisa ser revogada.

      Leve do RIPEAM para o TE-251

      • O pipeline de RAG, como a ferramenta search_kb sobre o manual da SW4, trocando OpenAIEmbeddings por bge-m3 no Ollama e persistindo o Chroma.
      • O prompt de grounding e a ideia de pôr data e hora no SystemMessage (no TE-251, a hora da leitura).
      • langchain-ollama, que o grupo já instalou: trocar o modelo é uma linha.
      • Streamlit ou LangGraph, se o grupo preferir a eles o servidor simples do harness.

      Deixe para trás

      • gpt-4o-mini e OpenAIEmbeddings: violam a regra de IA 100% local.
      • Temperatura 0,7: para dado de carro, use 0 a 0,2.
      • Histórico em string única: quebra o tool calling.
      • Tabela de códigos dentro do vetor: busca por semelhança confunde P0299 com P0229.
      • A chave sk-proj-… escrita no código: revogue em platform.openai.com.
      Sua pergunta

      Onde entra o script Python, se temos Ollama e Open WebUI?

      Cada peça tem um papel só. O Ollama roda o modelo e não sabe nada do carro. A Open WebUI é uma tela de chat. O Python é o que liga a SW4 ao modelo: ele coleta, guarda, busca o dado certo, confere a resposta e replica para o teatro. Sem ele, a Open WebUI conversa com um modelo que inventa a temperatura.

      Open WebUI

      Turma no teatro, no navegador ou no telão. Porta 8080.

      Página do HMT-1

      Operador no carro, por voz. Tela de 854×480; a Open WebUI é pesada demais aqui.

      API compatível com OpenAI · /v1/chat/completions · modelo “te251”

      Harness Python (o nosso script)

      • monta o prompt do modo carro ou teatro
      • executa as 6 ferramentas no SQLite e na base
      • confere números e idade do dado; cai para as regras se reprovar
      chamadas locais

      Ollama

      Só roda o modelo na GPU: /api/chat com tools, em 127.0.0.1:11434.

      Coletor e enlace (Python)

      coletor.py lê o OBD2 e grava no SQLite; enlace.py replica pelo MQTT.

      A. Open WebUI aponta para o harness

      recomendado

      O harness ganha uma rota no formato da OpenAI. Na Open WebUI, em Conexões, você cadastra http://localhost:8090/v1; o modelo “te251” aparece na lista. Toda pergunta da turma passa pelas ferramentas e pela checagem, e a mesma lógica atende o HMT-1.

      # web.py (esboço)
POST /v1/chat/completions
  msgs = corpo["messages"]
  r = harness.perguntar(msgs[-1]["content"],
                        historico=msgs[:-1])
  devolve {"choices":[{"message":
    {"role":"assistant","content":r["resposta"]}}]}

      B. Ferramentas dentro da Open WebUI

      funciona, com custo

      A Open WebUI aceita Tools e Functions escritas em Python. Dá para colar as ferramentas lá e fazer a checagem num filtro de saída. O problema é que a lógica fica presa à Open WebUI: o HMT-1 e os testes automáticos ficam de fora, e o código passa a viver em dois lugares.

      C. Open WebUI direto no Ollama

      só para testar o modelo

      É o padrão de instalação. Serve para conversar com o modelo e comparar versões, mas ele não tem acesso ao carro: qualquer número que ele der é inventado.

      Simulação didática. Os passos do RIPEAM seguem o código do .rar (chunks 1000/50, k=3, gpt-4o-mini a 0,7, LangGraph de um nó); os do TE-251 seguem o harness v0.2. Os trechos de manual e os valores do carro são ilustrativos. A rota /v1/chat/completions ainda não existe no harness: é a próxima mudança proposta.
